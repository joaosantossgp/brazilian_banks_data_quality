## Cinco fatos verificados

1. **Issues pertencem ao repositório; Projects organizam o acompanhamento.** Issues permitem planejar, discutir e rastrear trabalho. Projects oferecem tabela, quadro e roadmap no nível de usuário/organização, com referências diretas a Issues/PRs e sincronização de informações. Isso permite usar a Issue como registro de aceite e o Project como visão de status, sem copiar o corpo da Issue. [About issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/learning-about-issues/about-issues), [About Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects).

2. **Vincular o Project ao repo e adicionar suas Issues são relações diferentes.** O vínculo torna o Project acessível pela aba Projects do repo; essa listagem exige o mesmo usuário/organização proprietário. Definir o repo padrão facilita a criação de novas Issues nesse destino. Já adicionar Issues/PRs ao Project é uma operação própria, inclusive por URL; o vínculo não substitui essa inclusão. [Adding your project to a repository](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-your-project/adding-your-project-to-a-repository), [Adding items to your project](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-items-in-your-project/adding-items-to-your-project). A documentação também esclarece que tornar um Project privado afeta somente o Project, sem privatizar o repo ou suas Issues. [Managing project visibility](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-your-project/managing-visibility-of-your-projects).

3. **README é a porta de entrada humana e pode apontar para documentos internos.** GitHub apresenta o README aos visitantes e suporta links relativos para arquivos do repo. A separação proposta `README` para orientação humana e `AGENTS.md` para instruções operacionais de agentes é uma convenção deste projeto; a documentação de README consultada não estabelece semântica universal de `AGENTS.md`. [About the repository README file](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes).

4. **Releases distribuem versões ligadas a tags e podem carregar anexos separados.** Tags marcam um ponto do histórico do repo. Cada Release admite até 1.000 assets, cada arquivo abaixo de 2 GiB, segundo a documentação atual. A interface permite preparar rascunho, associar tag/branch, anexar arquivos e depois publicar; esses são recursos futuros, não ações autorizadas nesta pesquisa. Um checkout sem commit não fornece ainda o ponto de histórico necessário para essa rastreabilidade. [About releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases), [Managing releases](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

5. **Git LFS guarda ponteiros no Git e os arquivos grandes em armazenamento separado.** No uso do GitHub, isso continua sendo armazenamento remoto de conteúdo, recuperado por meio dos ponteiros. Portanto, LFS não satisfaz a premissa de manter os raw exclusivamente locais. Só seria opção caso houvesse uma necessidade futura autorizada de versionar binários grandes, com os limites do plano então conferidos. [About Git Large File Storage](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage).

## Opção preferida para um pesquisador e agentes

Recomendação de desenho, não plano executável: usar um repo como fonte dos arquivos de código, spec, plan, ADR e evidências de metadados; uma Issue por entrega ou decisão que precise de aceite, com links para o documento e para a evidência de verificação; e o [Project existente /3](https://github.com/users/joaosantossgp/projects/3) como quadro simples de status desses mesmos itens. Um único campo Status e links bastam inicialmente. O pesquisador conserva as decisões de unidade, janela e elegibilidade; agentes registram trabalho e evidência dentro do escopo autorizado.

`README` resume finalidade, limites, navegação e situação do estudo. `AGENTS.md` contém regras de execução e aponta para a spec/glossário/ADR existentes. Cada regra ou decisão tem um arquivo de referência; os outros documentos remetem a ele, evitando cópias divergentes. Como o repo atual foi informado como público, somente código, documentos e evidências de metadados preparados para divulgação e autorizados para publicação devem chegar a ele ou às suas Issues; o Project privado não protege esse conteúdo. URLs, datas e hashes pequenos podem acompanhar os documentos aprovados, excluindo credenciais e caminhos sensíveis; corpos raw e corpus financeiro permanecem locais conforme a guarda fornecida. Nenhuma publicação é autorizada por esta nota. Não é necessário tratar cada chamada de ferramenta como uma Issue.

Para artefatos grandes, a preferência atual é manter o armazenamento local e os respectivos manifestos/rastreabilidade. Se futuramente houver distribuição explicitamente autorizada de um pacote de derivados ou relatório fechado, Release associado a uma versão verificável é candidato mais simples que introduzir LFS. Isso não autoriza upload de raw nem publicação neste estágio.
